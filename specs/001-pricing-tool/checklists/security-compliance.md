# Security and Customer-Facing Compliance Checklist: CU Pricing Tool

**Purpose**: Tests whether the requirements in `spec.md` are complete, clear and consistent for
secrets, access control and roles, uplift limits and approvals, microbusiness and credit check
wording, customer and commission data in reporting, and keeping base rates and commission away from
customers. It checks the **written requirements**, not the code.

**Created**: 2026-10-30

**Feature**: [spec.md](../spec.md) (with [plan.md](../plan.md) and [research.md](../research.md) for context)

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

**How to read the references**:
- `Spec §FR-…`, `§US…` and `§SC-…` point to requirements, user stories and success criteria in `spec.md`.
- `Constitution §…` points to `.specify/memory/constitution.md`.
- `Plan R…` marks a question the plan or research already answers while the spec stays silent. Tick
  the item if you're content for the plan to hold that decision. Otherwise ask for the spec to be
  updated.

## Secrets handling

- [ ] CHK001 Does the spec name every secret the tool depends on (the POWWR licence code, the Meter Lookup client secret, the Entra client secret, and the POWWR and Microsoft Graph access tokens), or explicitly defer to the constitution for that list? [Completeness, Gap, Constitution §I]
- [ ] CHK002 Can FR-079 ("every request … MUST be kept") be met without storing the POWWR licence code, which travels inside every pricing request? Is there a requirement saying stored requests leave it out? [Conflict, Spec §FR-079, Constitution §I and §V; Plan R4]
- [ ] CHK003 Are requirements defined for what agents see when POWWR, the meter lookup or Outlook fail, including when the tool's own credentials are rejected (expired or revoked)? Do they rule out showing tokens, credentials or raw responses in messages? [Coverage, Exception Flow, Spec §FR-042, §FR-057, §Edge Cases]
- [ ] CHK004 Does the spec say how the tool can be used and tested before IT provides the app registration? Does it require any test sign-in to work only on developers' machines, never in a deployed environment? [Gap, Dependency, Spec §Assumptions "Dependencies", Constitution §I; Plan R2]

## Access control and roles

- [ ] CHK005 Does FR-001 name the staff group precisely (the constitution's "Pricing Tool Users", in our tenant)? Does the spec say what a signed-in member of that group with **no** role sees? [Clarity, Edge Case, Spec §FR-001, §FR-002, Constitution §I]
- [ ] CHK006 Is it defined whether someone with only the Admin role can create, price and send quotes? FR-002 gives Admins settings and reports, and FR-003 lets them see all quotes. [Ambiguity, Spec §FR-002, §FR-003]
- [ ] CHK007 Does the spec say whether Managers and Admins may only *view* other agents' quotes, or may also re-price them, change uplifts, generate PDFs or open them in Outlook? FR-003 says only "see". [Ambiguity, Spec §FR-003; Plan contracts/ui-routes.md]
- [ ] CHK008 Are access rules defined for stored customer PDFs: who may download them, and whether a download link works for anyone who can't see the quote? [Gap, Spec §FR-051, §FR-076, §US7-4]
- [ ] CHK009 Does the spec state that roles and quote ownership are enforced for every page and action, not only by hiding navigation? Do acceptance scenarios cover refusal in every restricted area? Settings (US8-5) and Reports (US9-3) are covered, but an Agent opening Approvals or another agent's quote is not. [Coverage, Gap, Spec §FR-002, §FR-003, §US5, Constitution §I]
- [ ] CHK010 Are requirements defined for how quickly removing someone from the staff group, or taking away a role, takes effect for a person who is already signed in? [Gap, Spec §FR-001, §FR-002]
- [ ] CHK011 Is FR-004 (every role sees base rates and commission in the tool) consistent with FR-088 (only Admins see reporting data *because* it holds commission and customer details)? Managers can already see the same figures quote by quote through FR-003. [Consistency, Spec §FR-003, §FR-004, §FR-088]

## Uplift limits and approvals

- [ ] CHK012 Does the spec say which limit applies to a person holding more than one quoting role, such as Agent and Manager? [Ambiguity, Spec §FR-002, §FR-058; Plan R13 uses the highest]
- [ ] CHK013 Is the meaning of a blank limit defined for a role, an individual agent or a supplier: no limit, or no uplift allowed? [Gap, Spec §FR-058, §FR-059]
- [ ] CHK014 Is it specified that going over *either* the unit-rate limit or the standing-charge limit, on its own, makes an option need approval, or puts it above the supplier maximum? [Clarity, Spec §FR-060, §FR-066]
- [ ] CHK015 Are supplier maximums per fuel, like role limits, or one value across both fuels? FR-058 says per fuel for roles; FR-059 doesn't say for suppliers. [Consistency, Spec §FR-058, §FR-059]
- [ ] CHK016 Is the scope of one approval request defined: does it cover only the *selected* options above the limit, or every one? Can one request cover several suppliers and terms? [Clarity, Spec §FR-061, §FR-065]
- [ ] CHK017 Is the whole lifecycle of an approval request specified, including whether an agent can withdraw it and what happens to a pending request after the agent lowers the uplift or re-prices? [Gap, Spec §FR-062, §FR-065, §Edge Cases]
- [ ] CHK018 Is behaviour defined when a manager's own request has no other manager available to decide it? [Edge Case, Gap, Spec §FR-063, §Assumptions "Visibility"]
- [ ] CHK019 Are requirements defined for what happens to already-priced options and pending or approved requests when an admin changes a role limit, agent limit or supplier maximum? Are they re-assessed, or fixed at pricing time? [Gap, Spec §FR-058, §FR-059, §FR-083]
- [ ] CHK020 Is the information a manager must see before deciding specified: the uplifts asked for against the limits, the commission involved, the customer and the agent's reason? [Completeness, Spec §FR-062, §US5-2]

## Microbusiness, credit check and other customer wording

- [ ] CHK021 Are the required parts of the microbusiness wording defined as mandatory? FR-047 lists the commission disclosure, the dispute resolution scheme (Energy Ombudsman) and a cooling-off period only "for example". [Ambiguity, Spec §FR-047]
- [ ] CHK022 FR-047 gives the credit check sentence word for word, while FR-050 says all customer-facing wording comes from admin settings. Is it clear which governs, and whether that sentence still needs compliance approval? [Conflict, Spec §FR-047, §FR-050, Constitution §IX]
- [ ] CHK023 Is it specified whether a PDF that still contains placeholder wording may be given to a customer, or whether generating it or opening it in Outlook is blocked until compliance approves the wording? [Gap, Spec §FR-050, §US3-4]
- [ ] CHK024 Is it defined how a wording item moves from placeholder to approved? Is the compliance approval (who approved it, and when) recorded separately from the admin who entered the text? [Gap, Spec §FR-050, §FR-082, Constitution §IX]
- [ ] CHK025 Is "the quote's annual consumption" for the microbusiness test justified against the regulatory definition, which concerns the business's total consumption, not one quote's sites? Is the limitation recorded as an assumption? [Assumption, Spec §FR-027, §US6-5]
- [ ] CHK026 Does the declaration route define what the agent records (employee count, turnover or balance sheet), how the €2m test is judged for figures in pounds, and whether a declaration-based flag can later be removed (and audited)? FR-028 covers only consumption-based flags. [Clarity, Gap, Spec §FR-027, §FR-028, §FR-079]
- [ ] CHK027 Are the commission disclosure requirements stated for each customer type, including whether microbusinesses or other small businesses must be shown the actual commission amount? Or is that left wholly to the admin-entered wording? [Clarity, Spec §FR-047, §FR-049, §Assumptions "Dependencies"]

## Customer and commission data in reporting

- [ ] CHK028 Is the "reporting store that Power BI can read" given access requirements matching FR-088 (Admins only)? It holds the same commission and customer data. [Gap, Spec §FR-087, §FR-088]
- [ ] CHK029 Is the content of the CSV export defined (which fields, and whether customer details are included)? Does FR-086 say what each export record holds (who, when, filters used, number of rows)? [Clarity, Spec §FR-085, §FR-086]
- [ ] CHK030 Is it explicit whether customer contact details (contact name, email address, phone) are left out of reporting records? FR-084 lists the customer name, business type, company number and postcode only. [Clarity, Spec §FR-007, §FR-084]
- [ ] CHK031 Does the retention requirement cover every copy of reporting data: the database records, files already sent to the reporting store, and the agent's or admin's downloaded CSVs? [Coverage, Spec §FR-080, §FR-085, §FR-087]
- [ ] CHK032 Does FR-084 include the commission basis (per year or whole contract) used for each pricing, so readers of the reporting store interpret commission correctly? FR-037 records the basis, but FR-084 doesn't list it. [Consistency, Spec §FR-037, §FR-084]
- [ ] CHK033 Is "estimated commission" in the Reports totals defined: which option (recommended or every selected one), from which event, and on which basis? [Ambiguity, Spec §FR-085; Plan R21]
- [ ] CHK034 Is there a requirement to protect CSV exports against spreadsheet formula injection, given that customer names and other free text end up in them? [Gap, Spec §FR-085; Plan R21]
- [ ] CHK035 Is anyone required to be told when reporting exports keep failing, beyond silent retries? [Gap, Exception Flow, Spec §FR-089, §SC-007]

## Base rates and commission never reach a customer

- [ ] CHK036 Is the full set of agent-only data defined in one place? The spec names base rates, uplift amounts, commission and supplier notes. Are the commission basis, limits, approval status, and POWWR's references and pricebook versions also agent-only? Is the full set of customer-facing outputs (PDF, Outlook draft and attachment, file name) listed alongside it? [Completeness, Spec §FR-004, §FR-033, §FR-049, Constitution §II]
- [ ] CHK037 Does FR-049 also exclude annual costs *before* uplift (POWWR's base annual price)? Those would reveal the commission as clearly as base rates do. [Gap, Spec §FR-049, §FR-047]
- [ ] CHK038 Does FR-049's exception ("except where the approved commission disclosure wording includes them") cover only commission, or can the disclosure wording also include base rates and uplift amounts? Only commission placeholders are defined. [Ambiguity, Spec §FR-049]
- [ ] CHK039 Do the disclosure placeholders say which option they refer to (the recommended one, or each offered option)? Do they say which commission figure they show (contract total, per year, upfront or monthly), and in what format? [Clarity, Spec §FR-049]
- [ ] CHK040 Are hidden places for agent-only data covered: PDF document properties (title, author, subject, keywords), the attachment name, and anything embedded in the file? [Coverage, Gap, Spec §FR-048, §FR-049, §FR-054]
- [ ] CHK041 Is an agent sharing their screen with a customer addressed, for example by a way to hide agent-only columns? Or is it explicitly accepted that results screens always show base rates and commission? [Gap, Spec §FR-004, §FR-033]
- [ ] CHK042 Is SC-003 measurable? Does it say how "contains no base rate, uplift amount or commission figure" is judged, including rounded or reformatted versions of those values? [Measurability, Spec §SC-003]

## Audit and retention
